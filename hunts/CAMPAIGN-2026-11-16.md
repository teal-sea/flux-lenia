# Campaign 2026-11-16, part C: species breadth

Branch `vizier/species-breadth-20261116`, base `ce00383`. Goal: at least 27 new species (30 total) that pass
the existing gates unchanged, each smoke-tested under `scripts/food_selection.py`. No engine changes.
No simulation runs on citadel: every screen, recording and smoke run is on InstaBox.

## Plan

### Which machinery (deviation from the brief, stated first)
The brief names `scripts/run_hunt.py`. That script sweeps `engine/physics.py` 2-channel non-reciprocal
genomes (`HUNT_00N`, gate `attractor_self_heal`, etc.) and writes `outputs/HUNT_00N_*_genome.json` of a
different type (`n_channels`, `K`, `kernel_radius`...). `scripts/food_selection.py` loads
`outputs/species/<SPECIES>_genome.json` with `nf.World.from_json` (`engine/neural_field.py`), whose schema
(`name, config, kernels, params, seed, origin, spawn_radius, spawn_peak, verified`) is the one written by
`scripts/discover.py`. SPECIES_001..003 came from `discover.py` (screen + curate), not from `run_hunt.py`.
A `run_hunt.py` genome cannot be loaded by `food_selection.py`, so I use the discover.py machinery, via a
new wrapper `scripts/species_batch.py` that imports its functions unchanged. `hunts/INDEX.json` belongs to
`run_hunt.py` (ids 1..5) and is left alone; species are recorded in `hunts/SPECIES_INDEX.json` (existing
structure, entries appended).

### Ids
Ids are screening seeds. Highest seed already recorded: 459 (`hunts/_screen`, bases 300 and 400). This
campaign screens contiguous seeds from 460, in shards, 8 single-thread processes per box
(`XLA_FLAGS="--xla_cpu_multi_thread_eigen=false intra_op_parallelism_threads=1"`), until 27 pass or 400 seeds
(460..859) are run. Every seed is recorded (pass / reject, gates, margins, wall time).

### Gates, as they stand at ce00383 (quoted, unchanged)
`engine/novelty_oracle.py viability_gates`:
- mass_conservation: `drift <= MASS_TOL` (`MASS_TOL = 1e-4`), drift = max|m - m0| / m0
- non_triviality: `concentration >= MIN_CONCENTRATION (6.0) and occupancy <= MAX_OCCUPANCY (0.45) and n_blobs >= 1`
- persistence: `len(tracker.survivors(min_life=max(3, tracker.frame // 4))) >= 1`
- activity: `moved > 0.02` cells/frame (most mobile organism with lifespan >= 5)
Reproduction (`discover.py`, `MIN_OFFSPRING_FRAC = 0.10`): `n_reproduction = len(tracker.reproduction_events(min_child_life=6)) > 0`,
i.e. a fission whose offspring survive >= 6 frames and carry >= 10% of the parent's mass.
Screen: 720 steps, tracked every 12, 128x128, 3 channels, float64.

### Promotion rule
A seed is a new species iff the four viability gates all pass AND `n_reproduction > 0` (exactly `discover.py curate`'s
rule for a random-origin winner). No hill-climb mutants, no score-based cherry-picking: passes are promoted in
ascending seed order, numbered from SPECIES_004. Promotion re-runs the seed (must still pass, deterministic),
does the phototaxis probe, a 900-step recording (png, gif, mp4), the report and the genome JSON with the same
code as `curate`. Behaviour detectors (pursuit, cyclic, phototaxis) are reported, not gates.
Caveats (recorded per species, not filtered): single qualifying division; no division in the 6-frame
recording run; strict > raw count; debris-dominated (>= 5 raw fissions per division); >= 60 organisms tracked;
>= 6 bodies at the end; cyclic gait flagged (FINDINGS 2.1, 2.2, 2.3, 2.5, 5). A suspicious species is still
promoted, with the labelled caveat, so the downstream worker can exclude it with the record.

### Smoke-test rule
On the box, for every new species: `python scripts/food_selection.py SPECIES 1 treat 1 3000 OUT per_channel`
(kappa 0) and the same with kappa 3. Pass iff the run completes, `final.body > 0`, `n_blobs_end >= 1` and
`max_rel_total_drift` at rounding (<= 1e-10). A species failing is recorded as "promoted, failed smoke" and moved
to `outputs/species/excluded/`. JSON validity: every new JSON is loaded with `nf.World.from_json` (the loader
`food_selection.py` uses) on citadel (import and parse only, seconds).

### Boxes
8 vCPU / 16 GiB, Debian 13, Python 3.13.5 venv in `/data/campc/venv`, jax 0.11.1, numpy 2.5.2, scipy 1.18.1
(the previous campaigns' pins), CPU, float64. Up to 8 boxes at once; all deleted after verified pulls.
Estimated cost about $0.07 per box-hour.
